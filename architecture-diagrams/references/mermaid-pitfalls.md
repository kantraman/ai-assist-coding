# Mermaid Pitfalls: Why Diagrams Fail to Render

Most render failures come from a short list of mistakes. Check this list when a diagram will not render, and apply it proactively when writing. These rules matter most when Mermaid is generated by smaller or non-Anthropic models, which tend to produce plausible but invalid syntax.

Every item below was tested against a current Mermaid renderer. Items are split into three severities:

- **BREAKS**: the diagram fails to render at all.
- **WRONG**: it renders, but the output is silently wrong.
- **FRAGILE**: it renders on current Mermaid, but older versions or other platforms (Confluence, Notion, older GitLab, wiki plugins) may break or render differently. Avoid these, since the target platform is usually unknown.

## 1. Flowchart

| Severity | Mistake | Broken | Fix |
|---|---|---|---|
| BREAKS | Reserved word as ID (`end`, `graph`) | `end["Done"]` | `finish["Done"]` |
| BREAKS | Unquoted label containing parentheses | `api[Order API (Node)]` | `api["Order API<br/>[Node.js]"]` |
| BREAKS | Unquoted edge label containing parentheses | `a -->\|Calls (HTTPS)\| b` | `a -->\|"Calls<br/>HTTPS"\| b` |
| BREAKS | `subgraph` without matching `end` | `subgraph x` with no `end` | every `subgraph` needs an `end` |
| WRONG | `o` or `x` directly after an arrow with no space becomes a circle/cross arrowhead | `a---oB` | `a --- oB`, or avoid IDs starting with `o`/`x` |
| FRAGILE | `\n` for line break | `"Line1\nLine2"` | `"Line1<br/>Line2"` |
| FRAGILE | Hyphen or space in ID | `order-api["x"]` | `orderApi["x"]` |
| FRAGILE | Bare quoted subgraph title (cannot be the target of an edge) | `subgraph "My Box"` | `subgraph myBox ["My Box"]` |
| FRAGILE | Special characters (`$ / : & %`) in unquoted labels | `a[Cost: $5]` | quote it and use words: `a["Cost 5 dollars"]` |
| QUALITY | Unlabeled arrows | `a --> b` | `a -->\|"Calls API"\| b` |

Always quote every label. It costs nothing and removes whole classes of errors.

Shape syntax quick reference:

```
id["rectangle"]      id(["stadium / person"])     id[("cylinder / database")]
id[["subroutine / queue"]]    id{{"hexagon"}}     id{"decision"}
```

Put `classDef` and `class` lines last, and keep comments (`%%`) on their own lines.

## 2. Sequence diagram

| Severity | Mistake | Fix |
|---|---|---|
| BREAKS | `;` inside message text | reword, use a comma or "and" |
| BREAKS | Missing `end` after `alt`, `opt`, `loop`, `par` | count them: every opener needs one `end` |
| WRONG | `#` inside message text silently truncates the message (`Item #1` renders as `Item`) | write "number 1" or "item 1" |
| FRAGILE | Participant used but never declared (Mermaid auto-creates it, but order and display name are then implicit) | declare all up front: `participant orderApi as Order API` |
| FRAGILE | Participant ids with spaces | `participant orderApi as Order API` |
| FRAGILE | Unbalanced `activate` / `deactivate` | use `+`/`-` shorthand (`a->>+b: call`, `b-->>-a: reply`) or omit activations |

Use `->>` for requests and `-->>` for responses.

## 3. Class / state / ER

- **Class** (FRAGILE): angle brackets in member types (`List<String>`) can break on some versions. Use `List~String~`.
- **State** (FRAGILE): use `stateDiagram-v2`, not the legacy `stateDiagram`. For display text with spaces, use `state "Awaiting payment" as awaitingPayment`.
- **ER** (FRAGILE): entity names with hyphens or spaces. Use `ORDER_ITEM`. Quote relationship labels that contain spaces: `: "appears in"`.
- **ER** (WRONG if reversed): attribute lines are `type name [PK|FK|UK]`, type first.

## 4. Version and platform portability

Write for the lowest common denominator:

- Start every block with the diagram keyword on the first line: `flowchart LR`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`, `erDiagram`. Use `flowchart` rather than the older `graph`.
- Native C4 blocks (`C4Context`, `C4Container`, and so on) do render on current Mermaid, but they are marked experimental, give poor layout control, and many platforms ship older Mermaid that lacks them. This is why this skill uses flowchart-based C4.
- Also avoid: `architecture-beta`, `block-beta`, `packet-beta`, `kanban`, `%%{init: ...}%%`, `click` callbacks, icon packs (`fa:fa-...`), backtick Markdown strings in labels, `@{ shape: ... }` node syntax, and ELK renderer options. Support varies by platform and version.
- HTML in labels: only `<br/>` and `<b>`. No `<img>`, `<span style>`, or links.
- One diagram per fenced block, fenced exactly as `mermaid`.
- GitHub renders `<b>` and `<br/>` correctly but ignores most `classDef` properties other than fill, stroke, color, stroke-width, and stroke-dasharray.

## 5. Last-resort simplifications

If a diagram still fails and you cannot test it:

1. Remove all `classDef` and `class` lines. Styling is the second most common failure after labels.
2. Remove `<b>` tags, keeping `<br/>`.
3. Replace every label with plain letters and digits, then re-add detail one node at a time.
4. Remove `subgraph` blocks, then re-add them.
5. Split the diagram into two.

Tell the user which simplification you made.

## Verifying

`python scripts/lint_mermaid.py <file.md>` catches everything marked BREAKS and WRONG above, plus most FRAGILE items as warnings. Add `--render` to also render each block with `mmdc` when Node and a Chromium browser are available (set `MERMAID_BROWSER` to a Chrome path if it is not auto-detected).
